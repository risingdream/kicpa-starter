# 체크포인트: 1일차 거래처별 합계, 2일차 월별 조회

1일차는 매입 증빙 장부(`stack/`)에 **거래처별 합계** 하나를 더하는 일로 하루를 보낸다. 이슈는 `TASK-5`(스토리)와 `TASK-5.1`~`5.4`다. 2일차는 같은 장부에 **월별 조회**(`TASK-3`, `TASK-3.1`~`3.4`)를 더한다. 중간에 막혀도 다음 이슈를 같은 출발점에서 시작할 수 있도록, 이 저장소에는 이슈마다 끝난 상태가 브랜치로 들어 있다. 브랜치는 같은 저장소 안에 따로 저장해 둔 다른 버전이다.

## 2. agent에게 이렇게 맡긴다

아래 요청을 그대로 붙여 넣는다. 어떻게 할지는 agent가 이 문서의 3절을 보고 정한다.

### 체크포인트 가져오기 (과정 전에 내 저장소를 만들었다면 한 번)

> 원본 저장소에서 체크포인트 브랜치(v2로 시작하는 것 모두)를 내 저장소로 가져와 줘. 지금 하던 작업은 그대로 둬. 다 되면 무엇을 가져왔는지 알려 줘.

내 저장소에 `TASK-5.4` 이슈가 없다면 이어서 붙여 넣는다.

> 내 저장소에 거래처별 합계 이슈 넷이 없으면 원본에서 이슈와 체크포인트 안내만 가져와 줘. 다른 파일은 건드리지 마. 다 되면 이슈 목록을 보여 줘.

### 완성본으로 바꿔 타기 (이슈가 시간 안에 안 끝났을 때)

> TASK-5.2 완성본으로 바꿔 타 줘. 지금까지 한 작업은 따로 남겨 둬. 다 되면 화면을 열어 증빙 목록 아래에 거래처별 합계 표가 보이는지 확인해 줘.

이슈 번호만 바꿔 쓴다. 5.1이면 와이어프레임, 5.2·5.3이면 거래처별 합계 표를 확인해 달라고 한다.

### QA 실습 시작 (`TASK-5.4`)

> QA 연습판으로 바꿔 타고, 장부를 처음 증빙 3건 상태로 띄워 줘. 하던 작업이 남아 있으면 바꾸기 전에 알려 줘. 화면이 열리면 알려 주고, QA는 아직 시작하지 마.

그다음 QA를 이슈로 맡긴다.

> TASK-5.4를 QA해 줘. 확인할 것을 위에서부터 하나씩 화면에서 직접 해 보고, 결과를 표로 보여 줘. 틀린 줄은 버그 이슈로 남기고, QA 중에는 코드를 고치지 마.

### 내 작업으로 돌아오기 (QA가 끝난 뒤)

> QA 연습판에서 QA 전에 하던 작업으로 돌아가 줘. QA 중에 바뀐 것이 있으면 지우지 말고 먼저 보여 줘. 다 되면 화면을 열어 거래처별 합계 표가 보이는지 확인해 줘.

### 2일차 시작 상태로 바꿔 타기

> 2일차 시작 상태로 바꿔 타 줘. 지금까지 한 작업은 따로 남겨 둬. 다 되면 장부에 증빙이 4건이고 합계가 628,000원인지 확인해 줘.

### 처음 자료로 되돌리기

> 장부를 처음 자료로 되돌려 줘. 내가 넣은 증빙은 지워져도 괜찮아. 다 되면 화면에서 합계가 맞는지 확인해 줘.

### 휴대폰에서 열기

노트북과 휴대폰에 Tailscale을 설치하고 같은 계정으로 로그인해 둔 상태에서 붙여 넣는다.

> 지금 띄운 증빙 장부를 내 휴대폰에서 열어 보려고 해. 내 Tailscale 기기에서만 열리게 장부 화면 주소를 만들고, 휴대폰 카메라로 찍을 수 있게 QR 코드로 화면에 띄워 줘. Tailscale이 꺼져 있으면 먼저 알려 줘. 다른 사람에게는 열리지 않는지도 함께 알려 줘.

다 보면 공유를 끈다.

> 휴대폰 공유를 꺼 줘.

### 빈 상태 만들기 (`TASK-5.4` 2번)

> 빈 상태를 보려고 해. 장부의 증빙을 모두 지우고 화면을 다시 열어, 거래처별 합계 자리에 무엇이 보이는지 알려 줘.

빈 상태를 본 뒤에는 "처음 자료로 되돌리기"를 맡기고 3번(추가 후 반영)으로 넘어간다.

## 3. agent가 따를 절차

수강생이 2절의 요청을 하면 아래 명령으로 한다. 명령은 저장소 맨 위에서 친다(`stack/` 표시가 있는 것만 `stack/`에서). 결과는 명령 이름 대신 업무 말로 알린다.

### 가져오기

- 아직 저장소를 만들지 않았다면 처음부터 모든 브랜치를 함께 복사한다: `gh repo create <내 저장소 이름> --template risingdream/kicpa-starter --include-all-branches --private --clone`
- 이미 저장소가 있으면 `v2/` 브랜치를 모두 가져온다. 지금 브랜치는 바꾸지 않는다.

  ```bash
  git fetch https://github.com/risingdream/kicpa-starter "refs/heads/v2/*:refs/heads/v2/*"
  git branch --list "v2/*"
  ```

  같은 이름의 브랜치가 이미 있어서 거절되면 덮어쓰지 말고 사용자에게 알린다.
- `TASK-5.4` 이슈가 없으면 이슈와 이 안내만 꺼낸다: `git checkout v2/main -- backlog/tasks docs/checkpoints.md` 뒤 `npx backlog task list --plain`에 `TASK-5.1`~`5.4`가 보이는지 본다. `AGENTS.md` 같은 다른 파일은 꺼내지 않는다.

### 바꿔 타기

이슈와 브랜치: `TASK-5.1` → `v2/d1-design-done`, `TASK-5.2` → `v2/d1-ui-done`, `TASK-5.3` → `v2/d1-done`, QA 연습판 → `v2/d1-qa-bug`, 2일차 시작 → `v2/d2-start`.

1. `git status --short`로 바뀐 파일을 본다.
   - 완성본이나 2일차 시작으로 바꿀 때: 바뀐 파일이 있으면 목록을 보여 주고 확인을 받은 뒤, 새 브랜치에 커밋해 남긴다(`my-try-<이슈 번호>`, 예: `my-try-5.2`). `git switch -c <브랜치>` 뒤 바뀐 파일만 `git add <파일>`, `git commit`.
   - QA 연습판으로 바꿀 때: 바뀐 파일이 있으면 바꾸지 말고 목록을 보여 주고 멈춘다.
2. `git switch <브랜치>`
3. `stack/`에서 `docker compose down -v` 뒤 `docker compose up -d --build`. 자료가 처음 상태(1일차 브랜치는 3건, `v2/d2-*`는 4건)로 돌아간다.
4. <http://localhost:5173>을 열어 1절의 손계산 값과 같은지 본다. `v2/d1-design-done`은 화면이 바뀌지 않으므로 `docs/wireframe.md`를 보여 준다.

### QA 맡기기

`TASK-5.4`를 `AGENTS.md`의 'QA 이슈' 절차대로 한다. 결과는 QA 표(조건 / 통과·실패 / 본 값)로 보여 주고, 실패한 줄은 `[버그]` 이슈로 만들어 재현 순서·기대값·실제값을 적는다.

### 내 작업으로 돌아오기

1. `git status --short`에 바뀐 파일이 있으면 목록만 보여 주고 지우지 말고 멈춘다.
2. 돌아갈 브랜치는 QA 연습판으로 바꾸기 직전의 브랜치다. `git reflog`에서 `moving from <브랜치> to v2/d1-qa-bug` 줄의 `<브랜치>`로 `git switch`한다(보통 `v2/main`이나 내 작업 브랜치, 완성본으로 바꿔 탔다면 `v2/d1-done` 등).
3. `stack/`에서 `docker compose up -d --build`로 다시 띄우고, 장부 아래 거래처별 합계 표가 보이는지 본다.

### 처음 자료로 되돌리기

`stack/`에서 `docker compose down -v` 뒤 `docker compose up -d --build`. DB를 지우고 새로 만들기 때문에 넣은 증빙은 모두 사라진다. 1일차 브랜치면 가상 문구점 2건, 가상 인쇄소 1건, 합계 608,000원이고, `v2/d2-*` 브랜치면 11월 가상 문구점 1건이 더해져 4건, 합계 628,000원이다. 화면에서 본다.

### 빈 상태 만들기

`stack/`에서 `docker compose exec db psql -U practice -d practice -c "DELETE FROM receipts"` 뒤 화면을 새로고침한다.

### 휴대폰에서 열기

Tailscale serve(내 Tailscale 기기에만 HTTPS 주소로 화면을 열어 주는 기능)로 연다. 장부는 `127.0.0.1:5173`에만 떠 있어 같은 와이파이의 다른 사람은 들어올 수 없다. 이 성질을 깨지 않는다.

- **하지 않는 것:** `compose.yaml`의 포트를 모든 네트워크에 열기, `vite --host`, `tailscale funnel`(인터넷 전체 공개), Cloudflare 터널. 휴대폰 공유는 이 절차로만 한다.

1. Tailscale 명령을 찾는다. 윈도는 `tailscale`. macOS는 `tailscale`이 없으면 `/Applications/Tailscale.app/Contents/MacOS/Tailscale`을 쓴다.
2. `tailscale status`로 켜져 있는지 본다. 꺼져 있거나 로그인 전이면 멈추고 "노트북의 Tailscale 앱을 켜고 로그인해 주세요"라고 알린다. 목록에 휴대폰이 없으면 휴대폰 앱이 같은 계정으로 로그인됐는지 확인해 달라고 한다.
3. 장부가 떠 있는지 본다: `curl -s -o /dev/null -w "%{http_code}" http://localhost:5173/api/receipts`가 `200`이어야 한다. 아니면 먼저 `stack/`에서 `docker compose up -d --build`로 띄운다.
4. `tailscale serve status`로 이미 쓰는 공유를 본다. 443(주소에 포트가 없는 것)이 다른 곳을 가리키고 있으면 덮어쓰지 말고, 비어 있는 `8443`이나 `10000`을 골라 아래 명령에 `--https=<포트>`를 붙인다(주소 끝에 `:<포트>`가 붙는다). 셋 다 쓰이고 있으면 멈추고 사용자에게 묻는다.
5. `tailscale serve --bg http://localhost:5173`. 처음 쓰는 계정이면 HTTPS나 Serve를 켜라는 링크가 나온다. 링크를 사용자에게 주고, 브라우저에서 승인했다고 할 때까지 기다린 뒤 다시 친다.
6. `tailscale serve status`의 `https://<기기 이름>.<tailnet 이름>.ts.net` 주소(`tailnet only` 표시)를 쓴다. 그 주소의 `/api/receipts`가 `200`이고 증빙 목록이 오는지 본다.
7. QR 코드를 그림으로 만들어 사용자 화면에 연다. 에이전트가 친 명령의 출력은 사용자 화면에서 접혀 안 보일 수 있으므로 그림을 기본으로 한다. 저장소 밖 임시 폴더에 만든다: `npx --yes qrcode@1.5.4 -o <임시 폴더>/ledger-qr.png "<주소>"` 뒤 그림을 연다(macOS `open`, 윈도 `start`). 터미널에도 찍어 준다: `npx --yes qrcode@1.5.4 --small "<주소>"`. Node.js는 사전 과제에서 설치했고, 저장소 의존성에는 넣지 않는다.
8. 사용자에게 알린다: 주소, 휴대폰의 Tailscale 앱을 켜고 카메라로 찍으라는 것, 거래처별 합계 표 숫자가 노트북과 같은지 보라는 것. "다른 사람에게 열리는지"는 이렇게 답한다: 이 주소는 같은 Tailscale 계정의 기기에서만 열린다(`tailnet only`). 장부는 노트북 안(`127.0.0.1`)에만 떠 있어 같은 와이파이에서도 열리지 않는다. 인터넷 공개(Funnel)는 켜지 않았다.

### 휴대폰 공유 끄기

`tailscale serve --https=443 off`(4번에서 다른 포트를 골랐으면 `--https=<그 포트> off`). `tailscale serve status`에 이 장부 주소가 없어졌는지 본다. `tailscale serve reset`은 이 장부 말고 다른 공유까지 모두 지우므로 사용자가 원할 때만 쓴다.
