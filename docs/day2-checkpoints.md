# 2일차 체크포인트: 거래처별 합계

2일차는 매입 증빙 장부(`stack/`)에 **거래처별 합계** 하나를 더하는 일로 하루를 보낸다. 이슈는 `TASK-5`(스토리)와 `TASK-5.1`~`5.3`이다. 중간에 막혀도 다음 블록을 같은 출발점에서 시작할 수 있도록, 이 저장소에는 블록마다 끝난 상태가 브랜치로 들어 있다. 브랜치는 같은 저장소 안에 따로 저장해 둔 다른 버전이다.

## 1. 블록마다 끝난 상태

| 브랜치 | 들어 있는 것 | 언제 쓰나 |
|---|---|---|
| `main` | 시작 상태. 장부 목록과 가상 증빙 3건, 이슈 `TASK-5`~`5.3`. 디자인시스템(Tailwind CSS·shadcn/ui) 패키지는 미리 받아 두었고 설정은 아직 없다 | B1을 시작할 때 |
| `day2-b1-done` | B1 완성본. 와이어프레임(`docs/wireframe.md`), 디자인시스템 설정과 표 부품, 증빙 목록 아래 거래처별 합계 표(**화면이 증빙 목록으로 직접 더한다**), `AGENTS.md`의 디자인 규칙 | B1이 1:15까지 끝나지 않았을 때, B2 시작 전에 바꿔 탄다 |
| `day2-done` | B2 완성본. `day2-b1-done`에 더해 **서버가 거래처별 합계를 계산**한다(`GET /api/receipts/by-vendor`, 부가세는 건별 부가세의 합). 화면 표는 서버가 준 값을 그대로 보인다 | B2가 2:00까지 끝나지 않았을 때 바꿔 탄다 |
| `day2-qa-bug` | QA 연습판. B2까지 끝난 상태에서 시작한다 | B3 QA 실습(`TASK-5.3`) |

가상 증빙 3건과 손계산 값:

| 거래처 | 증빙 | 공급가액 합계 | 부가세 합계 |
|---|---|---|---|
| 가상 문구점 | 120,000원, 38,000원 | 158,000원 | 15,800원 |
| 가상 인쇄소 | 450,000원 | 450,000원 | 45,000원 |

가상 문구점에 10,000원을 하나 더 넣으면 가상 문구점은 168,000원 / 16,800원이 된다. 반품 증빙 -38,005원의 부가세는 -3,800원이다(원 미만은 0 쪽으로 버림).

## 2. agent에게 이렇게 맡긴다

아래 요청을 그대로 붙여 넣는다. 어떻게 할지는 agent가 이 문서의 3절을 보고 정한다.

### 체크포인트 가져오기 (과정 전에 내 저장소를 만들었다면 한 번)

> 원본 저장소에서 2일차 체크포인트 세 가지(B1 완성본, B2 완성본, QA 연습판)를 내 저장소로 가져와 줘. 지금 하던 작업은 그대로 둬. 다 되면 무엇을 가져왔는지 알려 줘.

내 저장소에 `TASK-5` 이슈가 없다면 이어서 붙여 넣는다.

> 내 저장소에 2일차 이슈가 없으면 원본에서 2일차 이슈와 체크포인트 안내만 가져와 줘. 다른 파일은 건드리지 마. 다 되면 이슈 목록을 보여 줘.

### B1 완성본으로 바꿔 타기 (B1이 1:15까지 안 끝났을 때)

> 2일차 B1 완성본으로 바꿔 타 줘. 지금까지 한 작업은 따로 남겨 둬. 다 되면 화면을 열어 증빙 목록 아래에 거래처별 합계 표가 보이는지 확인해 줘.

### B2 완성본으로 바꿔 타기 (B2가 2:00까지 안 끝났을 때)

> 2일차 B2 완성본으로 바꿔 타 줘. 지금까지 한 작업은 따로 남겨 둬. 다 되면 화면을 열어 거래처별 합계 표가 보이는지 확인해 줘.

### B3 QA 실습 시작

> QA 연습판으로 바꿔 타고, 장부를 처음 증빙 3건 상태로 띄워 줘. 하던 작업이 남아 있으면 바꾸기 전에 알려 줘. 화면이 열리면 알려 주고, QA는 아직 시작하지 마.

그다음 QA를 이슈로 맡긴다.

> TASK-5.3을 QA해 줘. 확인할 것을 위에서부터 하나씩 화면에서 직접 해 보고, 결과를 표로 보여 줘. 틀린 줄은 버그 이슈로 남기고, QA 중에는 코드를 고치지 마.

### 내 작업으로 돌아오기 (B3가 끝난 뒤)

> QA 연습판에서 QA 전에 하던 작업으로 돌아가 줘. QA 중에 바뀐 것이 있으면 지우지 말고 먼저 보여 줘. 다 되면 화면을 열어 거래처별 합계 표가 보이는지 확인해 줘.

### 증빙 3건으로 되돌리기

> 장부를 처음 증빙 3건으로 되돌려 줘. 내가 넣은 증빙은 지워져도 괜찮아. 다 되면 화면에서 합계가 608,000원인지 확인해 줘.

### 빈 상태 만들기 (`TASK-5.3` 2번)

> 빈 상태를 보려고 해. 장부의 증빙을 모두 지우고 화면을 다시 열어, 거래처별 합계 자리에 무엇이 보이는지 알려 줘.

빈 상태를 본 뒤에는 "증빙 3건으로 되돌리기"를 맡기고 3번(추가 후 반영)으로 넘어간다.

## 3. agent가 따를 절차

수강생이 2절의 요청을 하면 아래 명령으로 한다. 명령은 저장소 맨 위에서 친다(`stack/` 표시가 있는 것만 `stack/`에서). 결과는 명령 이름 대신 업무 말로 알린다.

### 가져오기

- 아직 저장소를 만들지 않았다면 처음부터 모든 브랜치를 함께 복사한다: `gh repo create <내 저장소 이름> --template risingdream/kicpa-starter --include-all-branches --private --clone`
- 이미 저장소가 있으면 세 브랜치를 가져온다. 지금 브랜치는 바꾸지 않는다.

  ```bash
  git fetch https://github.com/risingdream/kicpa-starter day2-b1-done:day2-b1-done day2-done:day2-done day2-qa-bug:day2-qa-bug
  git branch
  ```

  같은 이름의 브랜치가 이미 있어서 거절되면 덮어쓰지 말고 사용자에게 알린다.
- `TASK-5` 이슈가 없으면 이슈와 이 안내만 꺼낸다: `git checkout day2-done -- backlog/tasks docs/day2-checkpoints.md` 뒤 `npx backlog task list --plain`에 `TASK-5`가 보이는지 본다. `AGENTS.md` 같은 다른 파일은 꺼내지 않는다.

### 바꿔 타기 (B1 완성본 `day2-b1-done`, B2 완성본 `day2-done`, QA 연습판 `day2-qa-bug`)

1. `git status --short`로 바뀐 파일을 본다.
   - 완성본으로 바꿀 때: 바뀐 파일이 있으면 목록을 보여 주고 확인을 받은 뒤, 새 브랜치에 커밋해 남긴다(B1이면 `day2-my-try-b1`, B2면 `day2-my-try-b2`). `git switch -c <브랜치>` 뒤 바뀐 파일만 `git add <파일>`, `git commit`.
   - QA 연습판으로 바꿀 때: 바뀐 파일이 있으면 바꾸지 말고 목록을 보여 주고 멈춘다.
2. `git switch <브랜치>`
3. `stack/`에서 `docker compose down -v` 뒤 `docker compose up -d --build`. 자료가 증빙 3건으로 돌아간다.
4. <http://localhost:5173>을 열어 거래처별 합계 표가 1절의 손계산 값과 같은지 본다.

### QA 맡기기

`TASK-5.3`을 `AGENTS.md`의 'QA 이슈' 절차대로 한다. 결과는 QA 표(조건 / 통과·실패 / 본 값)로 보여 주고, 실패한 줄은 `[버그]` 이슈로 만들어 재현 순서·기대값·실제값을 적는다.

### 내 작업으로 돌아오기

1. `git status --short`에 바뀐 파일이 있으면 목록만 보여 주고 지우지 말고 멈춘다.
2. 돌아갈 브랜치는 QA 연습판으로 바꾸기 직전의 브랜치다. `git reflog`에서 `moving from <브랜치> to day2-qa-bug` 줄의 `<브랜치>`로 `git switch`한다(보통 `main`, 완성본으로 바꿔 탔다면 `day2-b1-done`이나 `day2-done`).
3. `stack/`에서 `docker compose up -d --build`로 다시 띄우고, 장부 아래 거래처별 합계 표가 보이는지 본다.

### 증빙 3건으로 되돌리기

`stack/`에서 `docker compose down -v` 뒤 `docker compose up -d --build`. DB를 지우고 새로 만들기 때문에 넣은 증빙은 모두 사라진다. 장부에 가상 문구점 2건, 가상 인쇄소 1건, 합계 608,000원만 있는지 화면에서 본다.

### 빈 상태 만들기

`stack/`에서 `docker compose exec db psql -U practice -d practice -c "DELETE FROM receipts"` 뒤 화면을 새로고침한다.
