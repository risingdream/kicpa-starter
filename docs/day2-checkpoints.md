# 2일차 체크포인트: 거래처별 합계

2일차는 매입 증빙 장부(`stack/`)에 **거래처별 합계** 하나를 더하는 일로 하루를 보낸다. 이슈는 `TASK-5`(스토리)와 `TASK-5.1`~`5.3`이다. 중간에 막혀도 다음 블록을 같은 출발점에서 시작할 수 있도록, 이 저장소에는 단계별 상태가 브랜치로 들어 있다. 브랜치는 같은 저장소 안에 따로 저장해 둔 다른 버전이다.

## 1. 브랜치 셋

| 브랜치 | 들어 있는 것 | 언제 쓰나 |
|---|---|---|
| `main` | 시작 상태. 장부 목록과 가상 증빙 3건, 이슈 `TASK-5`~`5.3` | B1 화면 기획, B2 구현을 시작할 때 |
| `day2-done` | 거래처별 합계 완성본. API `GET /api/receipts/by-vendor`, 장부 아래 거래처별 합계 표, 증빙이 없을 때 "표시할 거래가 없습니다" | B2가 2:00까지 끝나지 않을 때 이걸로 바꾼다 |
| `day2-qa-bug` | `day2-done`에 일부러 결함 하나를 넣은 연습용 | B3 QA 실습(`TASK-5.3`) |

가상 증빙 3건과 손계산 값:

| 거래처 | 증빙 | 공급가액 합계 | 부가세 합계 |
|---|---|---|---|
| 가상 문구점 | 120,000원, 38,000원 | 158,000원 | 15,800원 |
| 가상 인쇄소 | 450,000원 | 450,000원 | 45,000원 |

가상 문구점에 10,000원을 하나 더 넣으면 가상 문구점은 168,000원 / 16,800원이 된다.

## 2. 브랜치를 내 저장소로 가져오기

**아직 내 저장소를 만들지 않았다면** 처음부터 모든 브랜치를 함께 복사한다.

```bash
gh repo create <내 저장소 이름> --template risingdream/kicpa-starter --include-all-branches --private --clone
```

**이미 내 저장소를 만들었다면** 원본에서 두 브랜치를 가져온다. agent에게 이렇게 붙여 넣는다.

> 원본 저장소에서 2일차 체크포인트 브랜치 둘을 가져와 줘. `git fetch https://github.com/risingdream/kicpa-starter day2-done:day2-done day2-qa-bug:day2-qa-bug`를 실행하고, 지금 있는 브랜치는 바꾸지 마. 끝나면 `git branch`로 브랜치 목록을 보여 줘.

내 저장소에 `TASK-5` 이슈가 없다면(과정 전에 저장소를 만든 경우) 이어서 이렇게 붙여 넣는다.

> day2-done 브랜치에서 이슈와 체크포인트 안내만 지금 브랜치로 꺼내 줘. `git checkout day2-done -- backlog/tasks docs/day2-checkpoints.md`를 실행하고 `npx backlog task list --plain`에 TASK-5가 보이는지 확인해 줘. 다른 파일은 고치지 마.

## 3. 브랜치 바꾸기

### B2에서 완성본으로 바꾸기 (2:00까지 안 될 때)

> 지금까지 한 변경을 `day2-my-try` 브랜치에 커밋해서 남겨 줘. 커밋하기 전에 바뀐 파일 목록을 보여 주고 내 확인을 받아. 그다음 `day2-done` 브랜치로 바꾸고, `stack/`에서 `docker compose down -v`와 `docker compose up -d --build`로 다시 띄워 줘. http://localhost:5173 장부 아래에 거래처별 합계 표가 보이는지 확인해 줘.

### B3 QA 실습 시작

> `day2-qa-bug` 브랜치로 바꿔 줘. 바뀐 파일이 남아 있으면 바꾸기 전에 멈추고 알려 줘. 바꾼 뒤 `stack/`에서 `docker compose down -v`와 `docker compose up -d --build`로 깨끗하게 다시 띄우고, 화면이 열리면 알려 줘. 아직 QA는 시작하지 마.

그다음 QA는 이슈로 맡긴다.

> TASK-5.3을 AGENTS.md의 'QA 이슈' 절차대로 진행해 줘. 인수 조건을 위에서부터 하나씩 화면에서 직접 해 보고, 결과를 QA 표(조건 / 통과·실패 / 본 값)로 보여 줘. 실패한 줄은 [버그] 이슈로 만들어 재현 순서·기대값·실제값을 적어. QA 중에는 코드를 고치지 마.

## 4. 자료 다루기

### 증빙 3건으로 되돌리기

B2에서 증빙을 더 넣었거나 QA 중에 자료를 바꿨으면 처음 3건으로 되돌린다. DB를 지우고 새로 만들기 때문에 내가 넣은 증빙은 모두 사라진다.

> `stack/`에서 `docker compose down -v`를 실행한 뒤 `docker compose up -d --build`로 다시 띄워 줘. 장부에 가상 문구점 2건, 가상 인쇄소 1건, 합계 608,000원만 있는지 화면에서 확인해 줘.

### 빈 상태 만들기 (`TASK-5.3` 2번)

> `stack/`에서 `docker compose exec db psql -U practice -d practice -c "DELETE FROM receipts"`로 증빙을 모두 지우고 화면을 새로고침해 줘. 거래처별 합계 자리에 무엇이 보이는지 알려 줘.

빈 상태를 본 뒤에는 위 "증빙 3건으로 되돌리기"를 하고 3번(추가 후 반영)으로 넘어간다.

## 강사용: 심어 둔 결함 (수강생에게 미리 보여 주지 않는다)

**무엇이 틀렸나** — `day2-qa-bug`에서는 증빙을 추가한 뒤 장부 목록만 다시 불러오고 거래처별 합계는 다시 불러오지 않는다. `stack/web/src/App.jsx`의 `submit`에서 `loadVendors();` 한 줄을 뺐다. `day2-done`과의 차이는 이 한 줄뿐이다(`git diff day2-done day2-qa-bug`).

**QA 표에서 이렇게 보인다** (2026-10-26 원격 Docker에서 화면으로 확인)

| `TASK-5.3` 인수 조건 | `day2-done` | `day2-qa-bug` |
|---|---|---|
| 1. 정상: 158,000/15,800, 450,000/45,000 | 통과 | 통과 |
| 2. 빈 상태: "표시할 거래가 없습니다" | 통과 | 통과 |
| 3. 추가 후 반영: 가상 문구점 10,000원 추가 → 168,000/16,800 | 통과 | **실패**: 장부 합계는 618,000원으로 바뀌지만 거래처별 표의 가상 문구점은 158,000원 / 15,800원 그대로 |

**짚어 줄 것**

- 새로고침하면 168,000원 / 16,800원이 제대로 나온다. 서버와 DB는 맞고 화면이 다시 묻지 않은 것이다. 그래서 이슈에 "새로고침하지 않아도"를 적어 두었고, 새로고침으로 넘기면 이 결함을 놓친다.
- `npm test`는 두 브랜치 모두 통과한다(9개). 테스트가 API만 확인하기 때문이다. "테스트 통과"와 "화면에서 확인"이 다른 이유를 보여 주는 장면이다.
- 버그 기록 예시: 재현 순서 "깨끗한 스택 → 거래처 '가상 문구점', 공급가액 10,000 입력 → [추가]", 기대값 "가상 문구점 168,000원 / 16,800원", 실제값 "158,000원 / 15,800원 그대로(장부 합계는 618,000원으로 바뀜)".
- 고치는 방법은 `submit`에서 거래처별 합계도 다시 불러오게 하는 것이다. 다시 확인할 때는 3번 한 줄만 다시 해 보면 된다. 고치지 못해도 기록이 남았으면 실습은 통과다.

**부가세 합계 기준 (B2 계획 검토 질문)** — `day2-done`은 거래처의 부가세 합계를 건별 부가세(원 미만 버림)의 합으로 낸다. 장부 목록의 부가세 칸을 더한 값과 맞추기 위해서다. 가상 증빙 3건에서는 공급가액 합계 × 10%와 값이 같아 화면으로는 차이가 나지 않는다. 차이는 `test/by-vendor.test.js`의 경계 사례(15원 + 15원 → 건별 합 2원, 합계 × 10%는 3원)로 보여 준다.
